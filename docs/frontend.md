# `apps/web`

Vite + Vue 3 + TypeScript, `vue-router`, `socket.io-client`. Минимальный, но
реально работающий фронтенд — не финальный дизайн, задача была проверить
весь живой цикл игры руками (см. `plan.md` про историю появления).

## Экраны (`src/views/`)

- **`LoginView.vue`** — вход/регистрация (тоггл одной формой).
- **`DashboardView.vue`** — дэшборд ведущего:
  - список треков с загрузкой файла (`<input type="file">` →
    `api.uploadTrackFile`) и `<audio controls>` для прослушивания;
  - CRUD плейлистов, добавление трека в плейлист (числовые поля
    `clipStartMs`/`clipEndMs`/`basePoints` — **не** waveform-редактор, это
    известное упрощение);
  - кнопка «Создать комнату» → переход на `/host/:roomCode`.
- **`HostRoomView.vue`** — живой экран ведущего. Подключается через
  `hostJoin` (не `joinRoom` — ведущий не становится `Player`), слушает
  `state`/`error`, показывает фазу/игроков/лидерборд, и кнопки,
  соответствующие текущей фазе (Start/Begin question/Accept-Reject/Advance).
- **`PlayerView.vue`** — форма входа игрока (код комнаты + ник + аватар-эмодзи)
  **и** живой игровой экран **в одном компоненте**, без смены роута/URL.
  Это осознанное решение: `joinRoom` создаёт нового `Player` при каждом
  вызове, так что если вход и игру разнести на два роута, перезагрузка
  страницы игрока во время игры плодила бы дублей. Текущий компромисс просто
  переносит ту же проблему на перезагрузку страницы вообще (см. `plan.md`
  про reconnect) — это не решение проблемы, а её локализация.

## `src/lib/api.ts`

Обёртка над `fetch` с `credentials: "include"` (нужно для httpOnly
cookie-сессии) и базовым URL из `VITE_API_URL` (по умолчанию
`http://127.0.0.1:3001` — см. ниже про `127.0.0.1` vs `localhost`).

`uploadTrackFile(file)` — весь цикл загрузки в три шага: `requestUploadUrl`
→ `PUT` файла прямо в S3 presigned-URL (без похода через наш сервер, как и
задумано в `CLAUDE.md`) → `readAudioDurationMs` (через скрытый `<audio>`-
элемент, `loadedmetadata`) → `finalizeTrack`.

## `src/lib/socket.ts`

Фабрика типизированного `socket.io-client` (`ClientToServerEvents`/
`ServerToClientEvents` из `@quiz/shared`), `withCredentials: true`,
`autoConnect: false` — компоненты сами решают, когда подключаться.

## Известные ограничения

- Нет waveform-редактора клипа (`wavesurfer.js`) — только числовые мс-поля.
- Нет QR-кода/короткой ссылки для входа игрока — только ручной ввод кода
  комнаты.
- Нет reconnect — перезагрузка страницы игрока создаёт нового `Player`.
- Нет тестов на фронтенде (ни unit, ни component).
- Минимальная вёрстка, без адаптации под реальный «большой экран + телефон»
  UX, который в итоге нужен для пати-игры.

## Особенность локальной машины разработки

На машине, где это собиралось, `localhost` на портах типа 3000/5173
перехватывался внутренними процессами Docker Desktop/WSL-relay и не доходил
до нужного процесса (curl получал пустой ответ или не тот сервер). Поэтому
везде — `CORS_ORIGIN` на сервере, `VITE_API_URL` на клиенте, и в адресной
строке браузера — используется `127.0.0.1`, а не `localhost`. Если это
воспроизведётся на другой машине без такого Docker-окружения — можно
вернуть `localhost`, они эквивалентны по функциональности.
