# `apps/web`

Vite + Vue 3 + TypeScript, `vue-router`, `socket.io-client`. Минимальный, но
реально работающий фронтенд — не финальный дизайн.

**Для сценариев взаимодействия экранов друг с другом — см. `flows.md`.**

## Роутинг (`src/router.ts`)

Намеренно разделён на «обычный пользователь» и «ведущий»:

| Путь | Компонент | Кто видит | Авторизация |
|---|---|---|---|
| `/` | `PlayerView.vue` | рядовой пользователь — заходит, вводит код, играет или открывает большой экран | нет |
| `/screen/:roomCode` | `ScreenView.vue` | устройство, подключённое к TV/проектору | нет |
| `/host/login` | `LoginView.vue` | ведущий | — |
| `/host` | `DashboardView.vue` | ведущий | cookie-сессия |
| `/host/:roomCode` | `HostRoomView.vue` | ведущий, живое управление | cookie-сессия (через socket `hostJoin`) |

`/` раньше было дэшбордом ведущего — теперь это специально самый простой
путь входа для человека, который просто хочет поиграть: `example.com` →
код комнаты → радио «Я игрок» / «Главный экран» → «Войти». Ссылка «Я
ведущий — создать игру» в самом низу ведёт на `/host`.

## `PlayerView.vue` — он же экран входа для всех (кроме ведущего)

Форма входа — **одна и та же** что для игрока, что для подключения
большого экрана:

- Код комнаты (общее поле).
- Радио-переключатель (сегментированный контрол, не нативные радиокнопки —
  `input` визуально скрыт, `label.role-option` стилизован через
  `:has(input:checked)`): «Я игрок» / «Главный экран».
- Если выбран игрок — показывается поле «Ник», аватар назначается
  **случайно** (`AVATARS[random]`), без ручного выбора.
- Если выбран экран — по сабмиту просто `router.push('/screen/' +
  roomCode)`, дальше всю работу делает `ScreenView.vue` — это не отдельный
  режим внутри `PlayerView`, а обычная навигация.

После входа как игрок — два независимых текстовых поля (артист, название).
После отправки поле **блокируется** (форма прячется, остаётся текст с ✓) —
и это не только декорация: сервер тоже откажет на повторную отправку, так
что обойти через devtools не выйдет.

**Реконнект**: при успешном входе в `localStorage` (`quiz:player`)
сохраняется `{roomCode, playerId, nickname, avatarId}`. При новом монтировании
компонент сперва пробует `rejoinRoom` с этими данными и только при неудаче
показывает обычную форму. Reconnect восстанавливает и счёт, и то, какие
поля уже были отправлены (чтобы лок не слетал после F5).

**Кик**: слушает `kicked`; если `payload.playerId` совпадает с собственным
— чистит `localStorage`, рвёт соединение, показывает «Ведущий исключил
тебя из комнаты» и форму входа заново.

## `ScreenView.vue` — большой экран

Подключается через `screenJoin` (без авторизации). Единственный клиент,
где реально есть `<audio>` и звук.

- Слушает `session.activePhaseStartedAt` (не `activePhaseIndex` —
  см. `shared.md` про то, почему именно таймстамп). При изменении:
  запрашивает `getCurrentClip` (ack, не хранится в обычном `state`), если
  клип для текущего вопроса ещё не закэширован, затем перематывает
  `<audio>` на начало нужной фазы и играет.
- Прогресс-бар — **`requestAnimationFrame`**, не `timeupdate` (тот фильтр
  раньше давал рваную анимацию и небольшой наезд за риску фазы). На границе
  фазы позиция принудительно «снэпится» ровно на отметку перед остановкой.
- Кнопка «Нажмите, чтобы включить звук» при первом открытии — обязательна,
  иначе браузер заблокирует звук: автоплей без прямого жеста пользователя
  на *этой конкретной странице* не разрешён, а команда на проигрывание
  приходит удалённо, с телефона ведущего.
- Сообщает `setAudioPlaying` обратно на сервер при реальном
  старте/остановке `<audio>` (через события `playing`/`pause`/`ended`) —
  это задел на будущее (buzz/bonus-режим), сейчас никем на экране игрока
  не потребляется напрямую.
- Лидерборд — с аватарками (`p.avatarId`).

## `HostRoomView.vue` — пульт ведущего (телефон)

Подключается через `hostJoin` (cookie), слушает **`hostState`** (не
`state`!) — это полная версия сессии, с чужими ответами, которую больше
никто не получает.

- **Звука и `<audio>` здесь нет** — экран (другое устройство) отвечает за
  реальное проигрывание. Полоска прогресса всё равно есть, но считается по
  настенным часам: `elapsed = Date.now() - activePhaseStartedAt`, без
  похода к серверу за клипом.
- Под полоской — `{artist} — {title}` текущего трека (подтянуто через
  обычный `GET /tracks`, т.к. хост и так авторизован и владеет треком) —
  чтобы судить ответы, не держа в голове, что это за песня.
- Статус экрана (🟢/🔴) и кнопка «Начать игру» **заблокирована**, пока
  `!session.screenConnected`.
- В лобби — список игроков с кнопкой «Кикнуть» у каждого, и «Отключить» у
  статуса экрана (обе — только пока `phase === "lobby"`).
- Навигация по вопросам — «← Пред.» / «След. →» (`gotoQuestion`), в обе
  стороны, не только вперёд.
- Кнопки фаз (1/2/3) — просто шлют `setActivePhase`, никакого локального
  аудио не трогают.
- Карточка ответа на каждого игрока — артист/название, статус (pending/✓/✗),
  кнопки принять/отклонить по каждому полю отдельно, редактируемое число
  очков (по умолчанию половина `basePoints` на каждое поле).

## `DashboardView.vue` — библиотека и плейлисты (`/host`)

Без изменений в сути со старой ревизии: загрузка треков (реальный upload
через presigned URL), CRUD плейлистов и их items, включая удаление целого
плейлиста и отдельного трека из него, создание комнаты → переход на
`/host/:roomCode`.

## `LoginView.vue` (`/host/login`)

Вход/регистрация. После успеха — `router.push("/host")`. Ссылка «Join as a
player instead» ведёт на `/` (не на `/play` — такого пути больше нет).

## `src/lib/api.ts` / `src/lib/socket.ts`

Без структурных изменений: `api.ts` — обёртка над `fetch` с
`credentials: "include"`; `socket.ts` — типизированная фабрика
`socket.io-client`.

## Известные ограничения

- Нет waveform-редактора клипа — три фазы (0–1с/1–4с/4–14с) захардкожены
  одинаково для всех треков, не настраиваются через UI.
- Нет QR-кода/короткой ссылки для входа — только ручной ввод кода комнаты.
- Нет тестов на фронтенде (ни unit, ни component).
- Игрок не узнаёт исход судейства по конкретному полю напрямую — только
  видит изменение своего общего счёта (намеренное упрощение, см. `plan.md`).
- Минимальная вёрстка, кроме формы входа — там сделан сегментированный
  радио-контрол специально под запрос «не дефолтные стили».

## Особенность локальной машины разработки

На машине, где это собиралось, `localhost` на некоторых портах
перехватывался процессами Docker Desktop/WSL-relay. Используется
`127.0.0.1` везде (`CORS_ORIGIN`, `VITE_API_URL`, адресная строка) — на
другой машине без такого Docker-окружения можно вернуть `localhost`.
