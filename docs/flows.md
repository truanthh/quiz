# Потоки — что происходит, когда

Этот файл отвечает на вопрос «а что конкретно летит куда по сети, когда
пользователь нажимает X» — читать после `shared.md`/`backend.md`/
`frontend.md`, если нужна не структура модулей, а пошаговый сценарий.

## Действующие лица и куда они заходят

| Кто | URL | Авторизация | Socket-роль (`socket.data.role`) |
|---|---|---|---|
| Игрок | `/` | нет | не задана (есть только `playerId`) |
| Большой экран | `/screen/:roomCode` | нет | `"screen"` |
| Ведущий | `/host/login` → `/host` → `/host/:roomCode` | httpOnly JWT cookie | `"host"` |

Важно: у обычного игрока и экрана **нет аккаунта** — только код комнаты.
У ведущего — обычный email+password аккаунт (`apps/server/src/auth`).

## Жизненный цикл одной игры

1. **Ведущий логинится** (`/host/login`) → попадает на `/host`
   (`DashboardView.vue`) → загружает трек(и), собирает плейлист.
2. **Ведущий создаёт комнату**: `POST /rooms` с `playlistId` → сервер читает
   плейлист из Postgres, зовёт `GameManager.createSession(hostId, items)` →
   получает `roomCode`, `phase: "lobby"` → клиент переходит на
   `/host/:roomCode`.
3. **Ведущий подключается по сокету**: `hostJoin({ roomCode })` →
   сервер проверяет JWT из cookie **самого сокета** (не из payload!) и что
   `session.hostId === userId` → сокет вступает в комнату Socket.IO
   `roomCode` **и** в `roomCode:host`, `socket.data.role = "host"`.
4. **Экран подключается**: кто-то на TV/ноутбуке открывает `/`, выбирает
   «Главный экран» → переход на `/screen/:roomCode` → `screenJoin({ roomCode
   })` (без всякой авторизации — тот же уровень доверия, что у игрока с
   кодом) → `socket.data.role = "screen"`, сокет вступает только в
   `roomCode` → `GameManager.addScreen()` → `session.screenConnected = true`
   → `broadcastState()`.
5. **Игроки подключаются**: на `/` выбирают «Я игрок», код + ник →
   `joinRoom({ roomCode, nickname, avatarId })` → `GameManager.addPlayer()`
   отказывает, если ник уже занят (без учёта регистра/пробелов) или если
   `phase !== "lobby"` → при успехе клиент сохраняет
   `{roomCode, playerId, nickname, avatarId}` в `localStorage` (для
   реконнекта, см. ниже).
6. **Ведущий жмёт «Начать игру»** — кнопка **неактивна**, пока
   `session.screenConnected === false`. По клику: `startGame` →
   `GameManager.startFreeTextGame()` (`game/freeTextGame.ts`) → отказывает,
   если плейлист пуст или экран не подключён → `phase: "question_active"`,
   `currentQuestionIndex: 0`.
7. **Ведущий выбирает фазу клипа** (кнопки «1», «2», «3» — захардкожены как
   0–1с/1–4с/4–14с от `clipStartMs`): `setActivePhase({ index })` →
   `GameManager.setActivePhase()` ставит `activePhaseIndex` **и**
   `activePhaseStartedAt: Date.now()` — именно второе поле меняется *на
   каждый клик*, даже повторный по той же фазе, и именно по нему (не по
   индексу) оба клиента — `ScreenView` и `HostRoomView` — решают
   «перезапустить проигрывание/анимацию», иначе повторный клик по той же
   фазе был бы no-op для Vue-вотчера.
   - `ScreenView` видит смену `activePhaseStartedAt` → вызывает
     `getCurrentClip` (приватный ack-запрос, не broadcast — доступен только
     `role === "host" | "screen"`, сервер резолвит `trackId` текущего
     вопроса в `Track` через Prisma и отдаёт `publicUrlFor(storageKey)`) →
     реально проигрывает mp3 в своём `<audio>`, кадр за кадром (`rAF`)
     репортит позицию в локальную полоску прогресса.
   - `HostRoomView` у себя рисует **ту же** полоску, но без звука — просто
     по формуле `elapsed = Date.now() - activePhaseStartedAt`, без похода
     к серверу за клипом.
   - `ScreenView` сообщает серверу `setAudioPlaying({ playing })` (только
     роль `"screen"` может), сервер кладёт это в `session.audioPlaying` и
     рассылает — это задел под будущий buzz/bonus-режим, сейчас ничем не
     потребляется на экране игрока.
8. **Игрок печатает ответ**: два независимых поля — артист, название.
   `submitFieldAnswer({ field, text })` → `GameManager.submitFieldAnswer()`
   → **отказывает**, если на это поле уже был ответ (проверка на сервере,
   не только в UI — иначе легко обойти через devtools) → кладёт
   `{text, judged: "pending", awardedPoints: 0}` в
   `session.answersByQuestion[currentQuestionIndex][playerId][field]`.
   Это поле целиком **не входит** в `PublicGameSession` (см. `shared.md`) —
   ни другие игроки, ни экран его не видят, только ведущий через
   `hostState`.
9. **Ведущий судит**: под полоской прогресса видно `{artist} — {title}`
   текущего трека (подтянуто через обычный `GET /tracks`, который у хоста
   уже и так есть), а ниже — карточка на каждого игрока с его
   артист/название и кнопками ✓/✗ по каждому полю отдельно, с
   редактируемым числом очков (по умолчанию пополам от `basePoints`).
   `judgeFieldAnswer({ playerId, field, correct, points })` →
   `GameManager.judgeFieldAnswer()` → если поле уже было судимо раньше,
   **сначала откатывает старое начисление**, потом применяет новое (не
   складывает). Повторное судейство в любую сторону — всегда корректный
   итоговый счёт.
10. **Ведущий листает вопросы**: `gotoQuestion({ index })` — в любую
    сторону, не только вперёд. Ответы предыдущих вопросов остаются в
    `answersByQuestion` по их индексу — вернувшись назад, ведущий увидит
    (и может пересудить) то, что там было.
11. **Ведущий жмёт «Закончить игру»**: `finishGame` → `phase: "finished"`.

## Кик (только в лобби, до старта)

- **Игрока**: кнопка «Кикнуть» рядом с ником в списке лобби →
  `kickPlayer({ playerId })` (только `role === "host"`) →
  `GameManager.removePlayer()` (откажет, если `phase !== "lobby"`) →
  сервер рассылает `kicked({ playerId })` **всем в комнате** (не только
  хосту), и **дополнительно** физически обрывает именно тот сокет через
  `io.in(roomCode).fetchSockets()` + `.disconnect(true)` — то есть кик не
  просто удаляет запись из `players`, он реально рвёт соединение.
  Кикнутый игрок получает `kicked`, сверяет `playerId` со своим, чистит
  `localStorage` и возвращается на форму входа с сообщением.
- **Экрана**: кнопка «Отключить» у статуса экрана → `kickScreen` (тоже
  только в лобби) → находит все сокеты с `role === "screen"` в комнате и
  дисконнектит их. Специальный код очистки не нужен: обычный
  `disconnect`-хендлер сам вызовет `removeScreen()` + `broadcastState()`,
  как при любом другом разрыве связи.

## Реконнект игрока (после F5)

Сокет-соединение не переживает перезагрузку страницы, а `joinRoom` создаёт
**нового** игрока при каждом вызове — то есть наивный повторный `joinRoom`
после рефреша либо заведёт дубля, либо вовсе откажет (`phase !== "lobby"`).
Вместо этого:

1. При успешном `joinRoom` клиент сохраняет `{roomCode, playerId, nickname,
   avatarId}` в `localStorage`.
2. При монтировании `PlayerView.vue` сначала проверяет localStorage; если
   что-то есть — зовёт `rejoinRoom({ roomCode, playerId })` **вместо**
   формы входа.
3. Сервер проверяет, что `playerId` реально существует в
   `session.players` этой комнаты → помечает `connected: true` →
   отвечает `{ session, myAnswers }`, где `myAnswers` — это ответы **именно
   этого игрока** за текущий вопрос (если были) → клиент восстанавливает
   лок «уже отправлено, менять нельзя» без дополнительных действий
   пользователя.
4. Если комнаты/игрока не нашлось (например, сервер перезапускали —
   `GameManager` ничего не персистит) — `rejoinRoom` отказывает,
   `localStorage` чистится, показывается обычная форма входа.

У ведущего отдельного реконнект-механизма нет и не нужно: `/host/:roomCode`
и так при каждом монтировании зовёт `hostJoin` заново, а это не создаёт
никаких новых сущностей — просто перепроверяет cookie и владение комнатой.

## Кто что видит — приватность одним взглядом

| Событие/канал | Кому летит | Что внутри |
|---|---|---|
| `state` | все в комнате (`io.to(roomCode)`) | `PublicGameSession` — без `answersByQuestion` |
| `hostState` | только хост (`io.to(roomCode:host)`) | полный `GameSession`, включая чужие ответы |
| `getCurrentClip` | ack на конкретный запрос, не broadcast | URL+тайминг клипа; доступно только роли `host` или `screen` |
| `kicked` | все в комнате | `{ playerId }` — каждый клиент сам решает, его ли это касается |

Склейка `state`/`hostState` в один `broadcastState()` — см.
`apps/server/src/index.ts`, функция `toPublicGameSession()` просто вырезает
одно поле (`answersByQuestion`) перед отправкой в публичный канал.
