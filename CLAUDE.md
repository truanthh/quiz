# Угадай мелодию — заметки по переписыванию

Пати-игра: до 8 игроков + 1 ведущий, все в одной комнате. **Три разных
устройства/роли**: телефон ведущего (управляет игрой), общий большой экран
(играет звук, показывает прогресс — на него все смотрят), телефоны игроков
(вводят ответ). Игрок печатает артиста и название трека; ведущий слушает и
сам решает, засчитывать ответ или нет.

Buzz (кто первый нажал — тот отвечает) в игре **сейчас не используется** —
это был первый вариант механики, его заменили на свободный ввод с живым
судейством (см. «Доменная модель» ниже, почему код остался, а не удалён).

Подробное описание — в [`docs/`](docs/README.md), и особенно
[`docs/flows.md`](docs/flows.md) — пошаговые сценарии «что летит куда».
Этот файл — быстрый онбординг и статус проекта.

## Структура репозитория — старое vs новое, прочитать первым

В репозитории сейчас **три** вещи:

- `server/`, `client/` — **оригинальная** локальная LAN-версия (чистый JS,
  Express + Socket.IO + Vue3). Один глобальный in-memory объект игры, без
  комнат, захардкоженный LAN IP. Оставлена только как референс для отдельных
  переиспользуемых кусков UI — **не строить поверх неё и не мержить с
  переписанной версией.**
- `apps/server` — **новый** бэкенд. TypeScript, настоящие комнаты, Postgres,
  S3. Это активная переписанная версия.
- `apps/web` — новый клиент на Vue3+TS. Реально работающий фронтенд с
  четырьмя экранами (см. ниже), не финальный дизайн.
- `packages/shared` — общие TS-типы/утилиты между `apps/server` и `apps/web`.

Была также заброшенная ветка `origin/forscience` — считать мёртвой.

## Стек

- **TypeScript везде** (сервер + клиент), npm workspaces (не pnpm).
- **Socket.IO** для realtime, **Express** для HTTP.
- **Postgres через Prisma** — аккаунты, библиотека треков, плейлисты. Сам
  игровой сеанс (`GameSession`) — **in-memory на процесс**, не персистентный.
- **S3-совместимое хранилище** для mp3/обложек через presigned URL. Локально
  — **`adobe/s3mock`** (не `minio`/`localstack` — оба упёрлись в login/
  license-стены, см. `docker-compose.yml`). **Важно**: AWS SDK v3 по
  умолчанию считает flexible checksums на S3-запросах — ломает
  совместимость с любой не-AWS реализацией (R2/MinIO/моки); в
  `apps/server/src/storage/s3Client.ts` выставлено
  `requestChecksumCalculation`/`responseChecksumValidation: "WHEN_REQUIRED"`.
- Много независимых `GameSession` на процесс Node — без Redis-шардинга
  (`@socket.io/redis-adapter` не подключён, добавить только если понадобится
  масштабирование за пределы одного инстанса).
- Клиент — **Vue 3**. Клипы делятся на **три захардкоженные фазы** (0–1с/
  1–4с/4–14с от `clipStartMs`) вместо визуального waveform-редактора — это
  известный временный компромисс (см. `docs/plan.md`).

## Доменная модель — две игровые машины

`packages/shared/src/domain.ts` + `apps/server/src/game/*`. **Это главное,
что должен понять новый человек**, иначе легко перепутать мёртвый код с
живым:

- **`game/transition.ts`** — исходная buzz-машина (`lobby →
  countdown_to_start → question_playing → (buzz) → answer_window → reveal →
  leaderboard → ... → wager_input → finished`). Чистая функция, 10 тестов,
  **но из текущего UI недостижима** — оставлена как задел под будущий
  бонусный вопрос с buzz-механикой, не удалена.
- **`game/freeTextGame.ts`** — **текущий, реально используемый** режим.
  `lobby → question_active → finished`, без единого FSM-события — просто
  набор чистых функций (`startGame`, `gotoQuestion`, `setActivePhase`,
  `submitFieldAnswer`, `judgeFieldAnswer`, `finishGame`), 21 тест:
  - Игрок шлёт `submitFieldAnswer` отдельно по полям «артист»/«название» —
    сервер **откажет на повторную отправку того же поля** (не только UI
    прячет форму — это намеренно, чтобы не обойти через devtools).
  - Ведущий судит каждое поле отдельно (`judgeFieldAnswer`): принять/
    отклонить + своё число очков. Повторное судейство откатывает старое
    начисление перед применением нового, не складывает дельты.
  - `gotoQuestion` — переход между вопросами в любую сторону, не только
    вперёд; ответы прошлых вопросов сохраняются по индексу.
  - `startGame` откажет, если **не подключён большой экран**
    (`!session.screenConnected`) — без экрана играть бессмысленно, это
    единственное устройство, которое реально проигрывает звук.

`GameManager.ts` — in-memory реестр комнат (`Map<roomCode, GameSession>`),
вызывает обе машины и держит побочное state: дубликаты ников при `joinRoom`
отбиваются, кик игрока/экрана работает только в lobby, подключение экрана
трекается отдельной картой сокетов (не частью `GameSession`).

## Socket.IO: кто что видит

Три Socket.IO-комнаты на одну игровую комнату (подробно — `docs/backend.md`
и `docs/flows.md`):

- `roomCode` — игроки + хост + экран, событие `state` (`PublicGameSession`
  — без чужих ответов).
- `${roomCode}:host` — только хост, событие `hostState` (полная сессия, с
  `answersByQuestion`).
- `getCurrentClip` — не broadcast вообще, приватный ack-запрос, доступный
  только ролям `host`/`screen` — иначе URL трека (а значит и ответ) утёк
  бы игрокам через их же сокет-трафик.

## Что уже сделано

- `packages/shared`: типы + socket-контракт для обеих игровых машин,
  `OperationResult<T>`, fuzzy match. Протестировано.
- `apps/server`: обе игровые машины (см. выше), auth (bcrypt+JWT,
  проверено против живого Postgres), S3 presigned upload (проверено
  против локального `adobe/s3mock`, включая реальную ID3-экстракцию),
  треки/плейлисты (включая удаление целиком и по одному item), централизо-
  ванный error-handling (`express-async-errors` — без него любая ошибка в
  async-хендлере роняла весь процесс, не только запрос), кик игрока/экрана
  (реально рвёт socket, не просто чистит запись), реконнект игрока через
  `rejoinRoom`. 48 юнит-тестов, `tsc --noEmit` чист.
- `apps/web`: 4 экрана с разделением ролей —
  - `/` — вход для рядового игрока: код комнаты + радио «Я игрок»/«Главный
    экран» (сегментированный кастомный контрол, не нативные radio) + одна
    кнопка «Войти». Реконнект по `localStorage` переживает F5.
  - `/screen/:roomCode` — большой экран, без логина, единственный владелец
    `<audio>`. Прогресс-бар на `requestAnimationFrame`, кнопка «включить
    звук» (обязательна из-за браузерных autoplay-политик).
  - `/host/login`, `/host`, `/host/:roomCode` — ведущий: логин, библиотека/
    плейлисты, живой пульт (без звука — только кнопки фаз/навигации и
    судейство ответов).
  - Весь сценарий — от создания комнаты до finished, включая кик и
    реконнект — проверен скриптами на `socket.io-client` против живого
    сервера.

## Известные пробелы / не начато

- **Нет waveform-редактора клипа** — три фазы захардкожены одинаково для
  всех треков.
- **Нет QR-кода/короткой ссылки входа** — только ручной код комнаты.
- **Игрок не видит исход судейства по полю** — только рост своего счёта.
- **Командный режим не прошит** — типы есть, логики нет ни в одной из двух
  игровых машин.
- **Нет тестов на `apps/web`.**
- **Реальный прод-бакет (R2) не проверен** — только локальный `adobe/s3mock`.
- **Старый buzz-FSM не перепроверялся** после всех изменений `GameSession`
  — если его когда-нибудь будут оживлять под бонусный вопрос, не
  полагаться на «тесты же зелёные», перепроверить интеграционно заново.

Полный список с приоритетами — `docs/plan.md`.

## Dev setup

```
npm install                                     # из корня репо (npm workspaces)
cd apps/server && npx prisma generate           # регенерация Prisma-клиента после правок схемы

docker compose up -d postgres s3mock            # из корня репо, нужен запущенный Docker Desktop
cd apps/server && npx prisma migrate dev --name init   # безопасно повторять — идемпотентно
cd apps/server && npx tsx scripts/bootstrapS3.ts       # создаёт локальный S3-бакет (один раз)

npm test --workspace=@quiz/server               # или --workspace=@quiz/shared
npm run dev --workspace=@quiz/server             # tsx watch, читает apps/server/.env
npm run dev --workspace=@quiz/web                # Vite, порт 5173
```

Скопировать `apps/server/.env.example` в `apps/server/.env` и заполнить
`DATABASE_URL`/`JWT_SECRET`/`S3_*`. Для локального `s3mock` рабочие значения:

```
S3_ENDPOINT=http://127.0.0.1:9090
S3_REGION=us-east-1
S3_BUCKET=quiz-tracks
S3_ACCESS_KEY_ID=test
S3_SECRET_ACCESS_KEY=test
S3_PUBLIC_URL=http://127.0.0.1:9090/quiz-tracks
```

**Особенность конкретной машины разработки (Windows + Docker Desktop):**
`localhost` на некоторых портах перехватывается процессами Docker Desktop/
WSL-relay. Если сайт не открывается или CORS не совпадает — везде
использовать `127.0.0.1` (`CORS_ORIGIN`, `VITE_API_URL`, адресная строка).

## Предложенный следующий шаг

Waveform-редактор клипа (`wavesurfer.js`) вместо трёх захардкоженных фаз —
самый заметный оставшийся разрыв между тем, что видит ведущий при
настройке плейлиста, и тем, что реально происходит в игре. После него —
персонализированная обратная связь игроку по судейству (сейчас видно
только через рост счёта).
